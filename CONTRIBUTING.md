# Purpose

This document defines the rules, standards and expectations for contributing to the **Marketing Research OS (MROS)**.

The objective is to ensure that all contributions maintain:

* scientific rigor
* methodological consistency
* modular architecture
* ethical integrity
* long-term maintainability

---

# Who Can Contribute

Contributions may come from:

* students
* researchers
* academics
* professionals in marketing, CRM, growth and AI
* collaborators of the project

All contributors must adhere to the principles defined in:

* ADR-0001
* PROJECT_PRINCIPLES.md
* PROJECT_CHARTER.md

---

# Core Contribution Principles

Every contribution must follow these principles:

## 1. Scientific Integrity

All content must be based on credible sources or clearly identified as:

* hypothesis
* interpretation
* conceptual framework
* practical recommendation

Fabrication of references is strictly prohibited.

---

## 2. Modularity

Each contribution must be self-contained and serve a single purpose.

Avoid:

* mixing unrelated topics
* duplicating existing content
* overly complex documents without structure

---

## 3. Clarity

Contributions must be:

* clearly written
* logically structured
* easy to understand
* free of unnecessary complexity

---

## 4. Reusability

All contributions should be designed for reuse across:

* academic research
* business applications
* future MROS modules

---

## 5. Transparency

All assumptions, limitations and uncertainties must be explicitly stated.

---

## 6. Ethical Use of AI

AI-assisted contributions must:

* be reviewed by a human
* avoid fabricated sources
* avoid misleading claims
* preserve intellectual honesty

---

# Repository Structure Rules

Contributions must follow the repository architecture:

```text
docs/
frameworks/
prompts/
templates/
checklists/
telex/
references/
```

Each file must be placed in the correct module.

---

# File Naming Conventions

Use clear and descriptive naming:

✔ GOOD

* customer-journey-framework.md
* crm-lead-management.md
* ai-literature-review-guide.md

✖ BAD

* file1.md
* final_version2.md
* newdoc.md

---

# Writing Standards

All documents must:

* use Markdown format
* include a title
* include purpose section
* include structured headings
* distinguish theory from application
* include references when applicable

---

# Quality Checklist Before Submission

Before submitting a contribution, verify:

## Content Quality

* [ ] Is the content scientifically grounded?
* [ ] Is the logic clear and structured?
* [ ] Does it add value to the framework?

## Structure

* [ ] Is the file modular and focused?
* [ ] Is it placed in the correct directory?
* [ ] Is naming consistent?

## Ethics

* [ ] Are there no fabricated references?
* [ ] Are limitations clearly stated?
* [ ] Is AI usage transparent?

---

# Review Process

All contributions should ideally follow this process:

1. Draft creation
2. Self-review
3. Alignment with principles
4. Integration into repository
5. Future revision if necessary

---

# What NOT to Do

The following are not allowed:

* plagiarism
* fabricated academic citations
* uncontrolled duplication of content
* mixing unrelated research areas in a single file
* replacing scientific reasoning with AI output
* ignoring repository structure

---

# Contribution Philosophy

The Marketing Research OS is not a static repository.

It is a living knowledge system.

Every contribution should improve:

* clarity
* scientific rigor
* usability
* reusability
* long-term knowledge value

---

# Final Note

Contributing to MROS means contributing to a structured scientific ecosystem, not just adding files to a repository.

Every contribution should strengthen the integrity and usefulness of the framework.
